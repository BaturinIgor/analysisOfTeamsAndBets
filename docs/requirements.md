# Анализатор ставок: требования (MVP — Dota 2)

Статус: согласовано 2026-11-04. Источник обсуждения — документ «Анализатор ставок Dota 2: оценка реализуемости и черновик требований».

## 1. Цель

Личный инструмент аналитики ставок на киберспорт. Он показывает матчи сегодня и в эфире, считает собственную вероятность исходов, сравнивает её с линией букмекеров, объясняет, на чём основана оценка, и ведёт симулятор бумажных ставок. Ставки система не делает: решение и ставку принимает пользователь вручную.

Первая дисциплина — Dota 2. Дальнейшие шаги (не входят в MVP): CS2 и шахматы → футбол, баскетбол, теннис → другие киберспортивные дисциплины → сравнение дисциплин на дистанции от 100 ставок.

## 2. Решения

| Вопрос | Решение |
| --- | --- |
| Интерфейс | Закрытый Telegram-бот; веб-панель — позже |
| Где работает | Mac пользователя (без платного сервера) |
| LLM | Claude Code по подписке пользователя, если это допускают условия Anthropic; иначе — опционально Claude API. Без LLM система работает, теряются только новости и текстовые обоснования |
| Язык | Python |
| Пользователи | Только владелец (белый список Telegram ID) |
| Момент ставки | Проверяем оба режима: до матча и сразу после драфта; симулятор считает их раздельно |
| Рынки | Победа на карте и победа в матче (в Bo2 — также ничья) |
| Турниры | Только Tier 1 и Tier 2 |
| Критерий сигнала | Перевес (EV) от 5%; фильтр «мин. вероятность + мин. коэффициент» (например 90% и 1.5) — настраиваемый |
| Букмекеры | BetBoom на старте; затем Fonbet и Pari для сравнения линий и вилок. 1xBet не используем: в РФ не лицензирован |
| Реальные деньги | Только после 100+ бумажных ставок с положительным CLV |

## 3. Источники данных

| Данные | Источник |
| --- | --- |
| Про-матчи, составы, драфты, длительность, убийства, график золота | OpenDota API (бесплатно, ~60 запросов/мин, ~2000/день) |
| Винрейт героев по патчам (про-сцена и Immortal), матчапы | STRATZ GraphQL API (бесплатный токен) |
| Расписание, турниры, история составов, стендины | Liquipedia API (с атрибуцией и соблюдением лимитов) |
| Коэффициенты (текущие и исторические) | OddsPapi (бесплатный тариф) — проверить покрытие BetBoom/Fonbet/Pari; иначе — сбор публичной линии с сайта БК |
| Новости о командах и игроках | Веб-поиск через LLM, только публичные заявления команд и игроков |

Замечания:
- Отдельного среза «13000+ MMR» в публичных данных нет; используем Immortal и винрейт героев в про-матчах текущего патча.
- Коэффициентов «сразу после драфта» за прошлые матчи нет нигде, поэтому система с первого дня сохраняет собственные снимки линии.

## 4. Функциональные требования

### Данные
- ТР-1. Загрузить историю про-матчей Dota 2 Tier 1–2 за 2 года: составы, драфт, патч, сторона, длительность, убийства по сторонам, график преимущества по золоту.
- ТР-2. Каждый час обновлять расписание на сегодня и список идущих матчей.
- ТР-3. Сохранять снимки коэффициентов с меткой времени: раз в 5–10 минут для матчей сегодня, чаще перед стартом, отдельный снимок сразу после драфта и закрывающий коэффициент.
- ТР-4. Сопоставлять названия команд и матчей между БК и статистикой (справочник синонимов с ручной правкой).
- ТР-5. Хранить составы с датами входа и выхода игроков и стендинами.

### Анализ команды и матча
- ТР-6. Форма команды (последние 10 карт и 30 дней), винрейт в текущем патче, винрейт с текущим составом, рейтинг Glicko.
- ТР-7. Личные встречи: число, счёт, длительность, убийства, закрывающие коэффициенты и исход (где они есть).
- ТР-8. Камбэки и потеря преимущества: доля побед при отставании больше N тыс. золота и доля поражений при таком же преимуществе (N настраивается, по умолчанию 10 000).
- ТР-9. Драфт: винрейт каждого героя в про-матчах и на Immortal в текущем патче, игры игрока на этом герое, синергии и контрпики.
- ТР-10. Новости за 7 дней: краткая выжимка, ссылки на источники, флаг риска (замена, стендин, визы, болезнь, конфликт).
- ТР-11. Карточка команды в Markdown: собирается из базы перед анализом и дополняется журналом новостей. Источник правды — база данных.

### Прогноз и рекомендация
- ТР-12. По каждому рынку: исход, коэффициент и БК, вероятность БК без маржи, вероятность нашей модели, EV.
- ТР-13. Вероятности считает статистическая модель (рейтинг плюс признаки), а не LLM. Модель проверяется на калибровку (Brier score, log-loss, график калибровки).
- ТР-14. Рекомендация показывается, только если выполнены пороги пользователя; иначе система прямо пишет «ставки нет».
- ТР-15. Обоснование: 3–5 главных факторов с цифрами и отдельный блок рисков.
- ТР-16. Сравнение коэффициентов между БК и сканер вилок (условие: сумма 1/k по исходам меньше 1) — включаются, когда подключена вторая БК.

### Telegram-бот
- ТР-17. Команды: `/start` (выбор спорта и дисциплины кнопками), `/today`, `/live`, `/match <id>` (полный анализ), `/team <название>`, `/value` (сигналы на сегодня), `/sim` (симулятор), `/export`, `/settings` (пороги и стратегия).
- ТР-18. Уведомление после драфта, если по матчу появился сигнал.
- ТР-19. Доступ только для Telegram ID из белого списка.

### Симулятор бумажных ставок
- ТР-20. Настройки: стартовый банк, период (от даты до даты), стратегия (фиксированная сумма, процент банка, дробный Келли, лесенка, догон — последние две с предупреждением о риске), пороги вероятности, коэффициента и EV, режим (до матча / после драфта).
- ТР-21. Не больше одной ставки на матч; в режиме «после драфта» — только после выбора всех 10 героев, по коэффициенту из снимка на этот момент.
- ТР-22. После матча — автоматическая проверка исхода и расчёт: прибыль, % от суммы ставки, % от текущего и от стартового банка, CLV. Для проигрыша — разбор, что пошло не так.
- ТР-23. Итоги: ROI, yield, максимальная просадка, серии, график банка, калибровка, сравнение стратегий на одних и тех же сигналах.
- ТР-24. Бэктест на прошлых датах — только там, где есть исторические коэффициенты, и без заглядывания в будущее: модель видит только данные до начала матча.

### Выгрузка
- ТР-25. Файл xlsx с листами «Матчи», «Ставки», «Итоги»: зелёным — выигрыши и положительный EV, красным — проигрыши и флаги риска. Открывается в Numbers и Excel. Параллельно CSV без цвета.

## 5. Нефункциональные требования
- Работает на macOS через launchd; при сне Mac сбор данных останавливается — рекомендуется не отключать питание.
- Ключи и токены — только в локальном `.env`, не в репозитории.
- Соблюдение лимитов API, кэширование ответов, аккуратный сбор публичной линии БК без авторизации.
- Архитектура позволяет добавлять дисциплины как отдельные модули.
- База: SQLite.

## 6. Этапы
1. Этап 0 (1 неделя): проверка источников и покрытия OddsPapi, сбор коэффициентов BetBoom, запуск накопления истории линии.
2. Этап 1 (2–3 недели): база, модель, бот с `/today`, `/live`, `/match`, выгрузка.
3. Этап 2 (2 недели): симулятор и новости.
4. Этап 3 (1–2 месяца): бумажные ставки до 100+ и вывод, есть ли перевес; подключение Fonbet и Pari, вилки.

## 8. Открытые вопросы
- Допускают ли условия Anthropic вызов Claude Code по подписке из локального бота — проверить до Этапа 2.
- Есть ли BetBoom, Fonbet и Pari в OddsPapi и насколько полно покрыта Dota 2 — проверить на Этапе 0.
